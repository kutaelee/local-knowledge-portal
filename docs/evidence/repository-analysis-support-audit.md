# 저장소 분석 기술지원 지식 검증 보고서

검증일: 2026-07-26
대상: Local Knowledge Portal 운영 DB의 최신 유효 저장소 분석과 현재 작업 트리

> 이 문서는 Qwen3.6 IndigoESB 분석을 시작하기 전의 정적 분석 기준선이다. 아래
> `미완료 또는 미확정`은 당시 상태를 보존한 기록이며 현재 완료 판정으로 사용하지
> 않는다. 세 프로젝트의 Qwen 분석·임베딩·15개 범주 평가가 끝나면
> `repository_analysis_report`가 생성하는 최종 IndigoESB 검증 보고서와 불변조건을
> 완료 근거로 사용한다.

## 실제 확인한 문제

- 최신 `local-knowledge-portal` 스냅샷에는 파일 80개, Claim 500개가 있었으나
  저장소 지식 80개 모두 `document_id`가 비어 있어 일반 문서·벡터 검색과 연결되지
  않았다.
- 저장소 분석 전용 검색은 단순 전체 문구 `ILIKE`였고 프로젝트와 스냅샷 필터가
  선택 사항이었다. `timeout 재시도`, `worker 처리 실패`, `설정 변경 영향` 표본
  질의는 모두 결과가 0개였다.
- 관계는 `CALLS`, `DEPENDS_ON`, `EXTENDS` 세 종류에 집중되어 있었다.
  `GpuQueuePage → GpuQueuePage`, `RootLayout → return`처럼 선언 자체와 예약어가
  호출로 기록된 오탐을 확인했다.
- 표본 지식 20개의 파일 존재 여부, 줄 범위, 원본 해시는 모두 일치했지만
  `symbol` 근거가 비어 있는 항목이 많고 구성요소 일반 설명 위주였다.
- 의존 패키지는 선언과 import 위치가 연결되어 있었지만 사용 symbol, 기능 영향,
  변경 영향은 저장하지 않았다.
- 평가는 근거 무결성 40건뿐이었고 답변 품질은 실행하지 않았다.
- 화면 생명주기 노드 안에서 단계 번호와 제목이 같은 영역을 사용해 겹칠 수 있었다.
- 화면에서 새 저장소 경로를 등록해 분석할 방법이 없었다.

## 구현한 변경

- 허용된 읽기 전용 `source_root` 하위의 절대 경로만 받는 분석 요청 API와 상태
  조회 API를 추가했다.
- 기존 `ingest_job`을 재사용해 `repository_analysis` 작업을 등록하고 워커가
  발견, 정적 분석, 검증, 합성, 평가, 저장을 수행하도록 연결했다.
- 워커 결과에 correlation/project/snapshot 식별자, 지표, 경고, 원문 저장 여부,
  로컬 모델 사용 여부를 기록한다.
- 검색에 프로젝트와 스냅샷을 필수화하고 stale 스냅샷을 제외했다. 여러 검색어 중
  실제 지식 필드와 일치하는 항목을 찾도록 보강했다.
- import를 별도 `IMPORTS` 관계로 기록하고 예외 발생·처리, 외부 요청, 재시도,
  설정 읽기, DB 읽기·쓰기를 구분했다. 선언 자기호출과 `return` 오탐을 제거했다.
- 예외 처리, 외부 요청·재시도, 데이터 흐름 지식을 근거 줄과 함께 합성하고 설정
  지식에도 선언 위치 근거를 연결했다.
- 근거 평가를 질문 50개와 장애 시나리오 15개, 총 65개로 확대했다.
- UI에 저장소 경로와 `분석하기` 버튼, 작업 상태 표시를 추가했다.
- 생명주기 노드의 번호를 독립 배지로 분리하고 제목을 별도 사각 노드에 배치했다.
  긴 제목은 줄임 표시하고 전체 설명은 툴팁으로 제공한다.
- 요약에 원본 확인, 부분 확인, 추가 자료 필요 지식 수를 구분해 표시한다.

- 임시 PostgreSQL을 새로 생성한 격리 통합시험: 31개 통과.
- 통합시험에서 분석 요청 등록, 상태 조회, 허용 경로 거부, 실제 워커 분석 및
  저장 완료를 검증했다.
- 임시 시험 DB는 종료 트랩으로 삭제되었으며 운영 DB는 변경하지 않았다.

- 수정 소스 기반 임시 개발 화면에서 운영 메뉴 안의 `레포 분석`이 페이지 이동 없이
  콘텐츠 영역에 표시되고, 경로 입력과 `분석하기` 버튼이 렌더링되는 것을 확인했다.

## 미완료 또는 미확정
- 65개 평가는 파일·symbol·line·hash의 근거 무결성 평가다. 실제 검색 답변의
  정답률, 주요 호출 흐름 90%, 설정 위치 95%, 의존 사용 관계 90% 기준은 아직
  측정되지 않았으므로 달성으로 보고하지 않는다.
- 동적 호출, 런타임 분기, 메시지 소비·발행, fallback, transaction 경계는 정적
  분석만으로 충분히 확인되지 않는다.
- 현재 schema에는 contradiction 전용 필드와 요청서의 세분화된 모든 검증 상태가
  없다. 이를 추가하려면 신규 migration 설계와 승인된 적용이 필요하다.
- 사람 기준의 실제 기술지원 답변 정답률은 아직 별도 평가하지 않았다.

## 롤백

변경한 API, 워커, 분석기, 합성기, 평가, UI, 시험 파일만 되돌리면 된다. 격리 시험
DB는 이미 삭제되었다.
