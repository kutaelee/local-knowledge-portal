# ADR 0011: 지식 품질 게이트와 사용자 승인

- 상태: Superseded by ADR 0013
- 날짜: 2026-07-24

## 배경

Codex 훅에서 관측한 파일 변경과 성공한 테스트는 작업이 실행됐다는 근거다. 그러나
`파일 N개 변경`이나 변경 파일 목록은 문제의 원인, 설계 결정, 재사용 가능한 해결
방법을 설명하지 않는다. 실행 근거 게이트만 통과한 작업을 자동 발행하자 최근 사례가
활동 요약에 머물렀고 검색 노이즈가 됐다.

임베딩 모델 `qwen3-embedding:0.6b`는 텍스트를 검색 벡터로 변환할 뿐, 사실 여부나
지식 가치를 판정할 수 없다. 선택적 생성 모델도 문구 정리와 분류를 보조할 수는
있지만 승인 권한이나 검증 근거가 될 수 없다.

## 결정

지식 승격을 다음 네 단계로 분리한다.

1. 훅과 collector는 사용자 지시, 변경 파일, 명령, exit code를 활동 이력으로 기록한다.
2. 결정론적 extractor는 의미 신호가 있는 작업만 후보로 만든다.
3. evidence gate는 실패·성공 명령, 변경 파일, 측정값 같은 관측 근거를 검증한다.
4. quality gate가 목표, 원인 또는 구현 방식, 조치, 검증 결과의 재사용 가능성을
   확인한 뒤 사용자가 `HUMAN_APPROVED`로 정식 사례 발행을 승인한다.

운영 기본값은 `LKP_KNOWLEDGE_AUTO_PUBLISH=false`다. API 발행 요청에는 명시적
`HUMAN_APPROVED` 확인과 reviewer가 필요하며 승인 시각을 후보 metadata에 남긴다.
Codex와 로컬 생성 모델은 후보를 제안할 수 있지만 스스로 승인하지 않는다.

관리 문서의 제목과 설명 문구는 `LKP_KNOWLEDGE_CONTENT_LANGUAGE`를 따른다.
현재 기본값은 `ko`이며 경로, 명령, 변수명, 모델명 같은 기술 식별자는 번역하지
않는다. 원문 보고는 별도 필드에 그대로 보존한다.

## 활동 보존

- 저신호 프롬프트, 읽기 전용 도구 호출, lifecycle-only 이벤트는 collector에서
  활동으로 승격하지 않고 처리 후 raw spool 파일을 제거한다.
- 승격된 사용자 지시, 종료 요약, 실패, 지식 근거는 계속 보존한다.
- 근거에 연결되지 않은 성공 도구 상세는 기본 30일 뒤 `rolled_up`으로 표시해
  기본 목록에서 숨긴다. 이 처리는 1시간에 한 번만 실행하며 DB 행을 삭제하지 않는다.
- 물리 삭제나 기간 단축은 별도 보존 정책과 사용자 승인이 있어야 한다.

## 기존 저품질 사례 처리

`deterministic-activity-v1`이 만든 일반적 파일 변경 설명 6건은 삭제하지 않고
`retired`로 전환했다. 후보·실행 근거·revision은 보존했고 후보는
`NEEDS_REVIEW`로 되돌렸다. 생성 Markdown은
`_generated/_retired/Knowledge-Cases`로 격리하고 해당 경로를 수집 제외했다.
원래 추출 문구는 후보 metadata에 보존한다.

## 결과

정식 사례 목록과 RAG 검색에는 원인과 조치가 설명된 사례만 남는다. 실행 성공과
지식 품질이 분리되며, 향후 로컬 생성 모델을 붙이더라도 사람 승인과 관측 근거를
우회할 수 없다.
